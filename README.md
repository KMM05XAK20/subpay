# SubPay

Telegram-бот + Mini App для оплаты зарубежных сервисов. Один и тот же Mini App
работает и для клиента, и для админа — роль определяется на сервере по
подписанному `initData` (`ADMIN_ID` из `.env`).

## Mini App

- **Клиент:** калькулятор и курсы, оформление заявки, реквизиты с таймером
  и копированием, статус-трекер, чат с админом, правила.
- **Админ** (переключатель «Админка / Как клиент» сверху): обзор с оборотом,
  профитом и графиком, очередь заявок с действиями (принять / отказ / оплата /
  в работу / выполнено / возврат), клиенты и блокировка, курсы и каталог сервисов.

Фронтенд — статика без сборки в `project/webapp/`, API — `project/web/`,
общая логика действий над заявками — `project/services/workflow.py`
(её же использует бот).

## Запуск

`.env`:

```
BOT_TOKEN=...
ADMIN_ID=...
DB_PASSWORD=...
REQUISITES=Банк, номер карты, получатель
WEBAPP_URL=https://subpay.example.com   # публичный HTTPS-адрес Mini App
```

`docker compose up -d --build`, затем повесь HTTPS-прокси (nginx/caddy) с
`subpay.example.com` на `127.0.0.1:8080`. Telegram открывает Mini App только по
HTTPS. Без `WEBAPP_URL` бот работает как раньше, кнопки приложения не
показываются.

Бот сам выставит кнопку меню «Открыть», а также `/app` и inline-кнопки в
уведомлениях, которые ведут сразу на нужную заявку.
